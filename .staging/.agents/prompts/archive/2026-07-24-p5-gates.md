## Step 3 — `gate.fhir` (test-first, informed by EXP-C5)

Two-step engine discipline throughout (pattern #1): execute (subprocess via the invocation wrapper; preserve raw OperationOutcome JSON verbatim alongside the run) and interpret (pure, versioned function → canonical findings + verdict).

* Findings envelope (pattern #6 → in implementation): `{:severity, :code, :locator {:format :fhir :path …} (from the OperationOutcome expression), :message, :engine {:name :version}, :native-ref}`.
* Verdict: `:rejected` iff any issue maps to error-and-not-terminology-suppressed per the EXP-C5-derived mapping table (the table is DATA in the namespace, versioned, cited to the results file); warnings/informational → `:pass` with findings; terminology-suppressed issues → contribute `:indeterminate` findings; overall verdict is `:rejected` > `:indeterminate` > `:pass` (worst-of).
* IG machinery: `-ig` wiring that resolves IG package artifacts from the lockfile (kind `:profile`) when the caller specifies them; unit tests with a stub; NO IG pinned in the lockfile this session.
* Batch: gate a directory (or a catalog) → per-file results.

## Step 6 — Contract pairing (the loop-closer)

The test this whole architecture has been building toward: for each of the five FHIR defect operators — mutate a valid corpus file, gate the mutant, and assert the gate's response matches the operator's contract. Honest classification required: expected outcomes are per-operator, not uniformly "rejected" —

* structurally detectable contracts (remove-required-element, wrong-type-value, malformed-date, duplicate-element/cardinality) → expect `:rejected` with at least one finding whose locator matches the mutation's locator and whose code plausibly corresponds to the violated constraint (assert locator match strictly; assert code membership in a small expected set derived from EXP-C5's observations);
* terminology-dependent contracts (invalid-code-value) → expect, offline, whatever EXP-C5 showed: likely `:indeterminate` findings or a warning-tier response — assert the observed class and record in the test's docstring that this defect is undetectable at the base/offline tier, catchable only with terminology/IG artifacts.

Also the Gate kind law as a test: gating never modifies its input (byte-identical before/after). Add the pairing outcomes as a small table to `docs/experiments.md` or a short `docs/gate-calibration.md` — the "which defects does which gate tier catch" knowledge is exactly what the motivating team needs; one page, honest, cited.

Commit: `Contract pairing: operators vs gate.fhir; gate law test`.
