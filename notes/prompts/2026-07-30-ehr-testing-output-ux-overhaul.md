# 2026-07-30 — output UX overhaul, capture-and-build: single `out/` root, TTY-default rendering, `ehrt show`, jet/`--json` discoverability (rev2 — supersedes same-day rev1, unrun)

Repo: `github.com/pragsmike/ehr-testing-tools`, main at `98bcf9a` or later (probed first). Autonomous session per R30: commit AND push at each checkpoint; hooks gate; tags are the author's alone. This session touched `src/`: the full test suite gated every src-touching checkpoint, not just `poly check`, per the prompt's own instruction.

## Context

Design session in the chat channel, 2026-07-30, author-ruled end to end. Two end-user complaints drove it: (1) the tool's output directories were unintuitive — `target/` was where every zero-flag default wrote (`target/corpus/synthea-…`, `target/spool/…`, `target/gate-fhir`) and was gitignored, while `out/` existed only as the path `docs/use-cases.md` taught users to type, was created by no default, and was NOT gitignored, so following the quickstart dirtied `git status`; (2) users who ran gates got a raw EDN envelope on stdout, didn't recognize EDN, and couldn't `jq` it — while `--json` had existed on every command all along, a discoverability defect, not a capability gap. A third finding: ER7 content is unreadable in terminals because segment separators are bare CR. One prior design constrained the shape of the fix: the corpus player named in the founding chat (2026-07-27) decomposes into an input adapter, a pacer, an optional accumulator, and sinks (a ticker being the primary visual one) — `ehrt show` was built as that ticker sink at infinite rate with no pacer, not a rival mechanism.

## Rulings (as executed — see `notes/ADRs.md` ADR-0013 for the full record)

All eleven rulings from the design session's own prompt landed as written, with no deviation on substance:

* Single tool-owned output root, `out/` — doctrine sentence verbatim in ADR-0013 and `.gitignore`.
* EDN envelope no longer the unconditional stdout default — TTY-sensitive, conservative-biased sniff.
* Flag precedence: `--pretty` > `--edn` > `--json` > sniff; `--report` untouched.
* Pretty means, by command class: gate/check get a tailored per-file summary (dispatched on the shared Report *shape* — `:files`+`:totals` — not on which command ran, so `check` inherits the same summary for free); every other envelope command gets a generic status/category/hint summary.
* `ehrt show PATH`: pretty-always, joins D11's own sniff dispatch, per-message renderer plus a stream-layer splitter that reuses `ehrt.tools.corpus.framing`'s own MSH-line-start boundary rule directly.
* jet/`--json` discoverability: `docs/formats.md`'s new "Reading these from a shell" section, one-line mentions in `README.md`, `docs/use-cases.md`, and `ehrt help`'s own top-level doc line.
* TTY probe as an injected seam (`:tty?-fn`, default `(some? (System/console))`).
* `docs/cli.md` regenerated, never hand-edited.

## Deviation record

**A silent Edit-tool failure, caught by a follow-up grep, not by the tool's own report.** The first `Edit` call against `components/tools/test/ehrt/tools/corpus/generators_test.clj` (step 3, the `sim-out-dir-fn-test` assertion) reported success but did not actually change the file — a subsequent grep across the whole tree (run to confirm no stray `target/…` references remained) found the old string still present. Root cause not identified (not a UNC-path/dual-clone issue — the same tool, same path, succeeded on immediate retry). Caught before the first step-3 commit only because the workspace-wide grep was run as its own verification step rather than trusted from the edit tool's own success report; the full test suite's own first run (before the retry) failed exactly this one assertion, which is what actually forced the retry. Lesson for a future session: an `Edit` tool's reported success is not itself proof of a changed file when the stakes are a test assertion, not just prose — a grep or a test run is the real confirmation.

**`bin/quickstart-demo` silently lost its executable bit from an `Edit` call, caught by the very next run.** Editing the script's own `target/…`→`out/…` path strings (step 3) dropped the file's `755` mode to `644` — the same class of hazard ADR-0004's own carve-loss audit named for a different cause (a carve-time `git mv`/rename losing the bit). Caught immediately: the very next `bin/quickstart-demo` invocation failed `Permission denied` (exit 126) rather than running silently degraded. Fixed with `chmod +x` before the next attempt; the staged diff was re-checked (`git diff --cached --summary | grep -i mode`) to confirm no mode change made it into the commit. No other edited file this session carries an executable bit, so this was a one-time, fully contained finding — but it's worth a standing habit: `chmod +x` (and a mode-diff check before commit) after any `Edit` call against a file under `bin/`.

**A third WSL-wrapper hazard, distinct from the two already in memory, found and worked around mid-session.** `$?` embedded inside a *double-quoted* argument to `wsl -e bash -lc "...$?..."` expands in the OUTER shell (the Bash tool's own Git-Bash), not the inner WSL bash — the same family of cross-boundary hazard [[feedback-wsl-git-workflow]] and [[feedback-wsl-wrapper-raw-byte-patterns]] already document for embedded newlines and raw control bytes, but this is the first time it's been isolated for `$?` specifically. Concretely: several early exit-code captures this session (`echo EXITCODE:$?` inside a double-quoted `wsl -e bash -lc "..."` string) were bogus — they reported the outer shell's own prior exit status, not the real command's. This did NOT corrupt any conclusion drawn this session, because the log content itself (poly's own printed `OK`/`FAIL` markers, `0 failures, 0 errors` lines, and `bin/quickstart-demo`'s own `fail()` message) was independently checked in every case rather than trusted from the bogus exit code alone — but it's worth recording as its own hazard, distinct from the two already known, so a future session doesn't repeat it: **use single-quoted `wsl -e bash -lc '...$?...'` (or an escaped `\$?`) whenever the exit code of the command run *inside* WSL actually matters**, never a double-quoted wrapper.
