## Context

A genuine cold-environment run (author, Git Bash/Windows side, 2026-07-30) of bare `bin/ehrt corpus generate` produced three defects in the trial-user experience: a `run!` shadowing warning from `ehrt.tools.sim` as the first line of output; `rejected (not-cached)` with no remedy text (the Temurin JDK archive wasn't in the artifact cache — Synthea's lane needs fetched artifacts before it can run); and an empty `out/corpus/` left behind by the rejected run. The author ruled, from this evidence: sim is the default, not Synthea — the cold-start experience itself is the argument, since sim is this project's own engine, mounted in-process per ADR-0005, needing zero external artifacts, zero subprocess, zero network. This reverses ADR-0015's own compatibility sentence ("bare `corpus generate` remains Synthea"), amended fix-forward, dated, per the ADR-0005-amendment precedent — not a rewrite of what that record decided for its own session.

## Rulings (as executed — full record in ADR-0015's own amendment)

* Bare `corpus generate` = `generate sim`, with sim's existing defaults (shared seed, `:patients 1`, `:emit "hl7"`), under the same D9 zero-flag contract. `generate synthea` is the explicit spelling for the Synthea lane, unchanged in behavior. `generate sim` remains valid and identical to bare.
* The `:not-cached` rejection and its siblings from `resolve-and-extract` (`:unknown-artifact`, `:extract-failed`, `:executable-not-found`) carry a `:hint` naming the literal remedy: `run: bin/ehrt artifact fetch --all` with `bin/ehrt doctor` as the diagnostic pointer.
* `ehrt.tools.sim` declares `(:refer-clojure :exclude [run!])` so loading it stops printing the shadow warning; the full suite's load output was swept for any other such warnings.
* Rejected runs leave the filesystem exactly as found: artifact resolution runs before output-directory creation in both generate lanes (and every other create-then-check site found by grep).
* `bin/quickstart-demo` pins `generate synthea` explicitly — it deliberately exercises the Synthea→FHIR gate lane; the flip changed what it types, not what it tests. README's first-touch command becomes bare `corpus generate` (sim, works cold); the Synthea lane is introduced immediately after with its fetch prerequisite in the right order.
* The bare-generate compatibility test from the prior (trial-UX) session was updated to pin the new contract (bare ≡ sim), not deleted.

## Deviation record

**use-cases.edn strips: all six moved to `generate synthea`, none stayed bare.** The decision procedure's default ("prefer keeping a strip bare unless it's genuinely Synthea-specific") never actually had to choose, since every bare-`generate` strip in the committed docs happened to already pass `--config-path config/synthea/synthea.properties` — a flag that only exists in Synthea's own params, not sim's. No strip was found that used bare `generate` for content that would work unchanged under the sim default; had one existed, it would have stayed bare per the same decision procedure.

**The `artifact-remedy-hint` landed in `kernel/artifact.clj`, not at the CLI boundary.** The prompt's own decision procedure named a fallback ("attach the hint at the CLI boundary... where a CLI-command hint is wrong" for a non-CLI caller) but also explicitly sanctioned the kernel-level default ("if kernel-level, keep it command-agnostic"). Kernel-level was chosen because the hint text (`bin/ehrt artifact fetch --all` / `bin/ehrt doctor`) is genuinely correct advice regardless of which of this workspace's several call sites (`corpus generate synthea`, `gate fhir`, `artifact resolve`, `doctor`'s own checks) surfaces the rejection — there is no other production consumer of `kernel/artifact.clj` in this workspace for whom that advice would be wrong (the only other caller, `projects/conformance`'s test harness, never renders `:hint` at all) — and a single shared site matches this ADR's own established "revise the hint text in one place" convention (already used for `:out-dir-exists`, prior session).

**No further shadow warnings found.** The full suite's load output was greped for `already refers to` both before and after the `run!` fix; only `run!` ever appeared, and it appears zero times now.

**Every `.mkdirs` site was already correctly ordered except one deliberately-untouched case.** The grep sweep for create-then-check ordering across `components/tools/src` and `bases/cli/src` found `generate.clj`, `intake.clj`, `generators.clj`, and `spool.clj` already checking every precondition before ever creating a directory — no reordering was needed for the two generate lanes, `intake!`, or `spool!`.
