## Context

The corpus player was named in the founding design chat (2026-07-27) and given a four-part decomposition in `notes/ADRs.md` ADR-0013's own player paragraph: input adapter, pacer, optional accumulator, and sinks (ticker, bed board, paced emission). Three of the four parts already existed as tested code before this session started: `ehrt.tools.corpus.framing`'s `:er7-multi` codec (the message-boundary splitter), `ehrt.tools.display/render-er7-message` (the per-message renderer, built for exactly this reuse), and an accumulator in the sim arc. This session built the pacer plus two sinks that compose from those landed parts.

## Rulings (as executed — full record in `notes/ADRs.md` ADR-0014)

All rulings from the design session's own prompt landed as written:

* Scope: pacer + ticker sink + paced file emission, this session. Bed board, accumulator wiring, a sim event-log input adapter, and the `ehr-testing-viz` placement question: deferred, recorded.
* Placement: `components/tools`, alongside `ehrt.tools.display`.
* Plan/execute split: `ehrt.tools.player/plan` is pure (no clock, no IO); the executor (`bases/cli`) folds it through an injected `:sleep-fn` and a sink function.
* Pacing semantics: `--rate` (stream-seconds/wallclock-second, default 60), lenient MSH-7 parsing (no HAPI dependency), input order preserved (never sorted), negative deltas clamped and counted, unparseable timestamps pace at zero and are counted (without corrupting later deltas), `--idle-cap` (default 5s) caps any single wait and is tallied separately as a skip, never conflated with a clamp.
* The cue rule extends ADR-0013's artifact-vs-display boundary: skip cues go to the ticker's own stream or stderr, never a data sink; paced file emission is byte-identical to an unpaced batch write through the same designator.
* Sinks: ticker (full block or compact `--ticker line`), and `--sink file:...` reusing the existing source-sink designator vocabulary. MLLP transport deferred per this session's own bail-out procedure (below).
* End-of-run summary through the standard TTY/`--pretty`/`--edn`/`--json` machinery (ADR-0013), unchanged.
