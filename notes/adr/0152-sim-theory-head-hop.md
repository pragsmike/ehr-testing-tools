## ADR-0152 — the sim-theory head hop becomes a translator, and the `.edn` turns out to have drifted already

**Status:** Accepted (author-directed, autonomous session per R30),
2026-08-18.

### Context

`roadmap.md#sim-theory-edn-hop` (OPEN, PRIORITY 3) carried ADR-0139's
finding C-1: `components/sim/docs/sim-theory-equations.txt` was, by its
own header, *"hand-derived"* from `sim-theory.edn` with *"no Clojure
translator"*, sitting at the head of a chain ADR-0136 had otherwise
fully registered (`equations -> .mermaid -> the .md's embedded block`).
Nothing gated the pair, so the `.edn` could drift while all three
downstream artifacts regenerated byte-perfectly from the stale half and
CI stayed green. ADR-0139 deliberately did not fix it: the honest fix
was either a translator or a checked-in agreement gate, and either is a
design question.

Author ruling, 2026-08-18: *"(a) edn single-source-of-truth, keep
equations. Rider."* — translator; the equations file stays committed as
a GENERATED artifact; the `:execute` two-laws rider rides this session.

The prompt required prediction (a) — run the translator into `target/`,
diff against the committed file, classify every hunk — with a STOP if
any equation LINE differed in content rather than position. **It did.**

`clojure -X:dev ...pipeline/write-equations-txt!` over `sim-theory.edn`
produced 13 equation lines against the hand file's 13. Ten matched byte
for byte. Three differed in text:

| hand `.txt` | generated from `.edn` |
|---|---|
| `... [Calibrate]  {feedback: churn-profile→churn-profile}` | `... [Calibrate]` |
| `... [SystemUnderTest]  {external: true}` | *(no annotation)* |
| `... [ToolsCorpusIntake]  {external: true}` | *(no annotation)* |

The root cause was one the row had not anticipated, and it is the real
finding of this session. **`sim-theory.edn` did not validate against the
`Pipeline` Malli its own header claimed it kept "exactly":**

```
sim valid?  false
sim explain: {:stages [nil x10 {:kind ["missing required key"],
                               :status ["missing required key"]} x2]}
pipe valid? true
```

Its two external stages (`:sut`, `:tools-intake`) sat **inside
`:stages`**, carrying `:external? true` but neither `:kind` nor
`:status`, instead of under the top-level `:external-stages` key
`palgebra.signature`'s schema has always provided. So
`pipeline->equations-text` routed them through `stage->equation-line`
rather than `external-stage->equation-line`, silently dropping
`{external: true}`. Rendered, that costs both boxes their
`stroke-dasharray: 5 5` — publishing a diagram that claims this repo
implements SystemUnderTest and ToolsCorpusIntake, when `docs/notation.md`
reserves dashed precisely for *never built by this repo*. Separately,
there was no schema key of any kind for Calibrate's feedback mapping,
whose loss would have removed the `Calibrate -- churn-profile -->
churn_profile` wire that ADR-0135 recorded as a known defect and
deliberately declined to fix — a silent drive-by repair.

The session STOPPED and reported, per
`rulings.md#R-stop-only-on-two-defensible-readings`: both readings were
defensible (repair the `.edn`, or accept the lossy output), and the
prompt's fence forbade `.edn` stage/equation-bearing key changes and
limited `pipeline.clj` to a header option. **Both remedies were
simulated in `target/` before the question was asked**, so the ruling
was made against evidence rather than a prediction:

- relocate the two entries to `:external-stages` -> `valid? true`, and
  the hand ordering (union before externals) is restored for free;
- derive `{feedback: X→X}` from `:kind :feedback` plus an output that
  re-enters `:inputs`.

Together those reproduced **all 13 hand equation lines byte for byte**,
leaving the `.mermaid` identical modulo arrow renumbering. Ruled: **A1 +
A2(a) — widen the fence by two**; rider lands regardless.

**Disclosed:** the red commit carries `pipeline.clj`'s renderer half.

#### The header decision, stated as the prompt required

A **wrapper** (`write-sim-theory-equations-txt!`), not a `:header`
option on `write-equations-txt!`. The banner is four lines of text, and
passing it as an `-X` string argument would put multi-line content
through shell quoting in the Makefile — the mangling class this repo
already bans for commit messages. `docsgen.clj`'s own `banner` was
**not** reused (HTML-comment shaped; the converter ignores only `#`
lines) and **not** generalised with a comment-prefix argument: it serves
markdown outputs, and parameterizing a helper in one namespace for a
single caller in another buys coupling with no second use. The banner
lives in `generated-comment-header` and is **pinned at 4 lines by
test**, so the load-bearing line count is now a test edit rather than a
hand-editing hazard.

The feedback annotation is **derived**, not a new schema key — `:kind`,
`:inputs` and `:outputs` already hold the fact, and a key would put the
same fact in two places for an editor to keep in step, which is the
exact defect this ADR closes one hop upstream. It is gated on `:kind`
rather than on the name coincidence alone: a `:transform` whose output
happens to share an input's name is not a loop.

### The rider

`:execute` produces `ground-truth-log`, and its `:laws` carried three
entries — determinism, the decide/evolve split, the catalytics — none
stating the contract the log satisfies. Two entries added, per
`rulings.md#R-law-surface-propagation`: the log is a vector of `Event`
(`GroundTruth`, `valid-ground-truth?`) valid at `schema-version` and
stamped into every manifest as `:event-schema-version`, with additive
changes keeping the version and anything else bumping it
(`classify-change`, `event-schema-test`); and `:t` is monotone within a
run as a RUN-level property (`run-t-monotone?`), never per-event, with
no run-boundary marker — a run IS the vector.

**Correction, disclosed:** the driving prompt named the predicate
`valid-log?`. No such var exists; the tree has `valid-ground-truth?`
over a `GroundTruth` schema (`event_schema.clj:530-538`). Probed before
writing — the same probe-before-acting discipline ADR-0139 recorded as
having caught every design-channel erratum so far, now at one more.

### Two findings the session produced rather than inherited

1. **Adding a TEST NAMESPACE moves `.agents/state-derived.md`**, the
   same way ADR-0143's note says adding an ADR or a register row does.
   The pre-push suite went RED at `MAKE_EXIT=2` on exactly one failure
   (186 -> 187 test namespaces, 43 -> 44 docs-tooling gates). The
   generalisation was not written down anywhere before this run found
   it. The harness reported that same background run as "exit code 0"
   because the wrapper ended in `echo | tee` — the captured `MAKE_EXIT`
   is the only reason the red was seen, exactly what
   `rulings.md#R-full-suite-before-push` and review-3 D2-6 exist for.
2. **A prompt premise did not survive the tree, and is corrected here.**
   The prompt's own link census concluded the equations file was
   referenced from "`.agents/**` records/prompts/plans only (history)".
   `.agents/state.md:73` is not history — it is the live hazard
   register, and it asserted the hand derivation as a standing hazard.
   Fix-forward with disclosure rather than STOP, one reading being
   clearly weaker: leaving a live register asserting a hazard this
   commit eliminated is not defensible. The bullet is rewritten as the
   CLASS (a freshness gate over a chain that excludes the chain's source
   proves only that the middle agrees with itself) rather than deleted.

3. **A hand-owned register has a line cap, and a "rewrite as the class"
   fix can breach it.** The close suite went RED a second time at
   `MAKE_EXIT=2` on `state-md-stays-within-its-line-cap-test`: finding 2's
   rewrite took `.agents/state.md` to 124 lines against a cap of 120. The
   gate's own message names raising the cap as *"the move this arc exists
   to make unavailable"*, so the bullet was compacted to five lines
   instead. Both of this session's two suite reds were caught only by the
   captured `MAKE_EXIT`, neither by the run's visible tail.

`components/sim-trajectory/docs/trajectory-computation.md:249-250` has
described the diagram as "mechanically regenerated from
`sim-theory.edn`" all along — ADR-0139's contradicting live sentence.
