## Deviation record

- **AR-5 golden baseline not captured before the first edit.** Step 1
  called for the fixed-seed golden run to run *before any edit*; this
  session's own preflight (task tracking) ran it after S1's edits were
  already made, discovered only when the S1 verify step needed a true
  pre-move baseline to diff against. Recovered non-destructively: `git
  stash` (the obvious fix) was blocked by the environment's own
  auto-mode safety classifier, so a throwaway `git worktree` at the
  pre-S1 commit (`c75269e`) stood in for it, removed after use — no
  working-tree risk taken, and the baseline it produced is exactly what
  AR-5 asked for, just captured a few steps late. Named here as a
  process gap for the next multi-stage extraction session's own
  preflight ordering, not as a baseline that's actually missing.
- **AR-7's "375" baseline superseded by its own instruction, not
  contradicted.** AR-7 states two things: a specific number (375, "at
  plan time") and a method ("recount at session start; the live count
  is the baseline"). Recounting at session start (403, using
  `deftest`+`defspec` forms, matching what `poly test`'s own "Ran N
  tests" actually reports) found a different number than the plan
  text's own stated figure — read as the method superseding the
  number, per AR-7's own words, not a deviation from the ruling. Full
  reconciliation math in the session record and ADR-0025.
- **Step 5's stale-path tripwire read as `ehrt.sim.gmf`/`ehrt.sim.compile-
  trajectory`, applied literally as two `str/includes?` substring
  checks** (the same shape the existing `ehrt.tools.` entry in the same
  family already uses) rather than as regex patterns — the step's own
  backslash-escaped notation (`ehrt\.sim\.gmf`) reads as either; the
  existing family's own precedent (plain substring checks, not regex)
  was followed for consistency with the rest of that test file, and
  because a substring check on a fully-qualified namespace token has no
  false-positive risk a regex would need to guard against here.
- **This prompt itself does not carry `[A]`/`[C]` provenance tags on
  its own Author rulings section**, despite `notes/ADRs.md` ADR-0007's
  dated note (2026-08-02, provenance-adoption-rider session, same
  calendar day) ruling that convention active law "effective from the
  item-14 prompt onward." Not fixed retroactively (this archive
  reproduces the prompt verbatim, per this directory's own convention)
  — named here as a finding for whoever tracks prompt-authoring
  compliance next, most likely because this prompt was drafted in the
  design channel before the provenance-adoption-rider session ran that
  same day, not confirmed either way.
- No other deviations. Every other author ruling (AR-1 through AR-6)
  and every step was executed as written; both named escalation
  surfaces (Step 2's require-graph contradiction, AR-3's façade
