SESSION PROMPT — micro-arc: string-diagram terminal-output result nodes (Q1 a, Q2 b)

Drafted by the design channel, 2026-08-14, against a fresh public clone at `00bdad7` (ADR-0134 close, tree clean, tag `stable-20260814-exact-name` verified on `46b82ba`).

Context

Every single-equation palgebra diagram in the 21 generated use-case pages shows its inputs and dead-ends at the operation box: the signature line says `datum × profile-artifact → pass + rejected + no-verdict [Gate]` but nothing wires out. Channel-witnessed on the live tree (`docs/use-cases/profile-tier-hl7v2-conformance-gating.md`) and mechanism-pinned: `components/palgebra/tools/resource_equations_to_mermaid.py:351-355` emits output wires only for `{discard:}` outputs (red sinks) and `{feedback:}` edges, and `classify_types` (:226) has no terminal-output class at all — a codomain that is neither discarded nor consumed downstream gets no node and no wire. Multi-stage diagrams (`docs/dev/pipeline.md`) mask this because each stage's outputs are the next stage's inputs. The string-diagram skill's own SKILL.md wire table carries the same gap (discard and feedback map to wires; plain outputs map to nothing), so this is a shared design gap in script + skill doc together, not script-vs-spec divergence.

This is a docs/tooling micro-arc: zero corpus `src`, zero `demos`, zero module JSON — no oracle claim is made or owed.

Author rulings, verbatim

* Charter + rendering + style + scope: "Q1 a. Q2 b. Micro-arc."
   * Q1 a — one result node per coproduct summand, wired `Op -- name --> node`; a discarded summand still goes to its red sink; a summand consumed by any other equation in the file stays an inter-op edge (the existing producer map arbitrates); only truly-terminal outputs get result nodes.
   * Q2 b — result nodes get a visually distinct tint so domain and codomain are tellable at a glance (never the source grey).

Step 2 — Green: script + skill doc, co-landed

In `resource_equations_to_mermaid.py`:

1. `classify_types`: add a terminal class — outputs that appear in no equation's inputs, are not in any `discard`, and are not the source of any `feedback` mapping. Return it alongside the existing four.
2. Node emission: a new section after the sink block — `%% --- Result types (terminal outputs) ---` — emitting, for `t` in `sorted(terminal)`, `{slugify(t)}_out(["{t}"])`. The `_out` suffix is mandatory: a type can be both consumed and terminally produced (enrichment pass-through, `catalog → catalog [Enrich]`), and its result node must not collide with its source node ID.
3. Wire loop: in the per-equation output pass, extend the existing discard branch: `elif out in feedback-sources: (existing feedback wire, unchanged)`, `elif out in terminal: {op_slug} -- "{out}" --> {slugify(out)}_out`. Intermediates continue to render as inter-op edges via the producer map, untouched.
4. Styling (Q2 b): a new style block — `%% Result types (terminal outputs): green rounded` — for each terminal node: `style {slug}_out fill:#e8f5e9,stroke:#2e7d32, color:#1b5e20`. Colors are channel-recommended (distinct from source grey `#f5f5f5` and the red sink class); adjust only if a collision with an existing class emerges, and disclose the adjustment in the commit message.
5. Determinism: result nodes and styles emitted in sorted order; no existing emission reordered.

In `.agents/skills/string-diagram/SKILL.md`, same commit: the wire table gains a plain-output row (operation → green result node, one node per coproduct summand, `_out` suffix), the styling section documents the result class, and any worked example whose expected output the change affects is updated to match.
