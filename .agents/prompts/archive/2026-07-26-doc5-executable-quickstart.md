README's Quickstart is the most-copied block in the repo and, since

by a gate. After this session: the quickstart's commands live in a

this session builds states the invariant it encodes and what each
failure mode means, and every check is proven *able to fail* before
it is trusted to pass — a check that has never tripped is a claim,
not a measurement. §7's two failure modes apply all session: a
taught command that fails against the repo is a finding
(LOC-1's genus — stop the step, report; the quickstart was
sweep-verified in CLI-2, so expect none, but expectation is not
evidence); a check that misencodes its own invariant is an
escalation, never a silent patch.

Author rulings in effect: **The script runs the README's commands
verbatim** — same spellings, same order, comments and `$PATIENT_FILE`
shell substitution included; the teaching text is the tested text,
and any divergence between them is exactly the rot this wave exists
to catch, so the script may not "improve" a command (an improvement
belongs in the README first, and this session expects to make none).
**Two gates, split per ENF-1's fast/slow doctrine** — *freshness*
(the README fence and the script agree) is a cheap text comparison:
it joins ci.yml's fast tier, and the pre-push hook only if that is a
one-line addition to the existing hook, otherwise CI only, noted;
*execution* (the commands actually run green) is integration-tier —
it joins `integration.yml` and is never wired per-push. **The
freshness check is structural, per §7** — extract the fenced block's
command lines (normalize: strip comment-only lines and blanks; keep
order and continuation lines) and compare against the script's
command lines as an ordered list; the invariant, stated in the
check's own output on failure: *every command the README teaches is
a command the script runs, in the same order, and vice versa*. No
substring matching — §7's self-reference hazard is live here too:
this prompt itself archives containing quickstart command text, so
any check that greps broadly instead of extracting from the one
README fence is structurally compromised from birth. **Per-step
invariants live in the script** — each taught command carries its
expected exit code as an assertion (a helper like
`expect <code> <cmd...>` keeps it readable); expected codes come from
Step 0's map, not assumption — if a taught gate step legitimately
exits 1 or 3 by design, the script asserts that exact code, because
`set -e` alone would mistake a teaching moment for a failure.
**Tree-clean postcondition** — after a full run, `git status
--porcelain` is empty (the structural encoding of ADR-0005's
promise); the script may create only under gitignored paths, and if
Step 0 finds any taught command writing tracked space, that is a
finding about the quickstart — stop, report. **Cache honesty** — the
taught fetch commands are part of the quickstart and stay in the
script verbatim; against integration.yml's warm cache they no-op
fast, and cold they do real work: both are correct, neither is
special-cased. **Sensitivity is proven, not presumed** — Step 2
demonstrates the freshness check tripping (against a scratch copy
with one command line altered — never by committing a broken state)
and Step 1 demonstrates one per-step assertion tripping (wrong
expected code against a scratch invocation); both demonstrations are
recorded as evidence, then discarded. **Scope fence** — no SETUP.md,
no strips, no new teaching content; README's quickstart text changes
only on evidence of a defect, which is a stop-and-report first.
