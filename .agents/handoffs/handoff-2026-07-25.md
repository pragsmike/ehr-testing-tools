## Mistakes and Lessons

1. **The absorbing ranking (R3).** The design ruled `no-verdict` ranks
   above `:rejected` in `worst-of`. Real Synthea corpora mix
   terminology-suppressed findings (thousands per file) with genuine
   defects, so every file aggregated to `:no-verdict` — absence placed
   into an order absorbs. Falsified by measurement (3062/7736 on one
   mutant bundle), caught by the integration suite, revised
   mid-session to the current projection ranking. Lesson: D10's
   "different type position" phrasing was the warning; when a design
   says two things are different kinds, don't put them in one order.
   ADR-0010 records the rejected alternative with the measurement.
2. **A ruling arrived by misclick** (the mid-R3 ranking choice) and
   happened to be correct. The record was repaired afterward to carry
   the reason, not the accident — the projection frame in ADR-0010.
   Lesson: when process luck produces a right answer, retrofit the
   rationale immediately or the archive teaches superstition.
3. **Source-reading without probing (CAL-1).** The agent hypothesized
   from HAPI source that a rule fires-but-downgrades for corrupted
   segment names. Live probe: nothing fires at all
   (`:validation-exceptions []`). The corrected finding is stronger —
   the blind spots are not configuration-reachable. Lesson: probe
   before registering; the register's adversarial-reader clause
   applies first to its own author.
4. **Prompt premises can be stale (ENF-1).** The prompt braced for a
   NIST-infrastructure licensing pause on cold-cache fetch; the
   lockfile's three artifacts are GitHub release assets (EXP-D3 never
   adopted). Lesson: threat models need the same inventory-first
   discipline as everything else.
5. **Silent test vacuity (R2).** `cognitect.test-runner` does not
   derive discovery dirs from `:extra-paths`; without explicit
   `:dirs`, `palgebra/test` would have been green-by-omission forever.
   Facts-register F20; also F21 (`:exclude` vs `:excludes`
   singular/plural split between the runner and its `.api`).

## Dead Ends Explored (deliberately, on paper)

- **Adjunction between abstract/lowered layers**: assessed, not
  adopted — the section/fiber structure (`lower ⨟ erase = id`,
  fiber-local rewrite soundness) gives ~80% of the value without
  invented preorders. Revisit only if a real cost-dominance order
  emerges (design §III.4).
- **Sigma-diffing as the v2 generation route** (diff successive FHIR
  states into v2 messages): rejected in favor of the native event-tap
  framing — state is a fold of events; differentiation can't recover
  collapsed events or trigger-event semantics. Relevant only if
  EXP-A3 ever re-inflates.
- **Three dropped v2 operators** (drop-PID, corrupt-PID-name,
  blank-non-header-field): not dead ends but measured blind spots —
  probed `:pass` at judge.v2's tier. They are EXP-D3's acceptance
  criterion now, not failures.

## Technical Notes

- **WSL-only git** is hook-enforced (pre-commit and now pre-push);
  builds/tests run in WSL (JDK 17, Clojure CLI). Windows side is for
  file edits only.
- **Test discovery**: `:dirs` explicit in `:test`/`:coverage` aliases
  (F20). Coverage floor lives in the `:coverage` alias
  (`--fail-threshold 85`) — one source of truth, local == CI.
- **Golden check**: `make pipeline && make use-cases &&
  git diff --exit-code docs/pipeline.md docs/use-cases.md` — the
  cheap proof that renderer/signature changes are behavior-neutral;
  also a scope tripwire (a diagram diff in a session that shouldn't
  touch `pipeline.edn` means creep).
- **Integration suite** (`make integration`) takes ~10 minutes (real
  FHIR validator subprocess + Synthea generation); artifacts cache
  via `artifacts.lock.edn`. Contract pairing within it is the
  polarity regression: `:rejected` reads as success there. Any change
  forcing edits to that suite has crossed the judge/policy boundary —
  stop and reassess.
- **ER7 substrate** (`corpus.er7`): `limit -1` splits everywhere —
  trailing-field preservation is the point (the PipeParser hazard);
  the two adversarial fixtures exist to catch regressions there.
- **Locator v2 grammar**: `SEG`, `SEG[n]`, `SEG-F`, `SEG-F[n]`,
  `SEG-F.C`, `SEG-F.C.S`; MSH off-by-one documented at the grammar
  boundary, resolved one layer down. Operators consume the *parsed*
  locator.

## Watch-Outs for Successor

- **The prompt-session methodology**: chat designs and writes a
  dated prompt (house style: context paragraph, Read-first list,
  "Author rulings in effect", numbered steps with commit messages,
  self-archiving instruction); Code executes; prompts archive to
  `.agents/prompts/archive/` as provenance. Rulings-in-effect are
  written as settled — the author ratifies or strikes before pasting.
- **Stop-tripwires work; keep writing them.** Three sessions running,
  an agent falsified a premise from the design, itself, or the
  prompt-writer, because prompts paired rulings with evidence
  discipline and explicit stop conditions. Cheap to write, repeatedly
  decisive.
- **Conviction-bounded catalogs**: no operator ships without a
  resident judge that convicts it. Dropped candidates are recorded
  (operators.clj docstring + judge-calibration.md), never silently
  omitted.
- **History stays put**: archived prompts, experiment records, spent
  plans keep their paths with status markers; provenance links are
  load-bearing. Don't relocate `judge-gate-refactor.md`.
- **`:policy` is a reserved word** for the verdict→action layer
  (ADR-0009); the finding field is `:disposition`. Don't reintroduce
  the collision.
- **`.agents/prompts/archive/*` is never edited** — records, not
  living vocabulary; greps for old names will hit them; that's
  correct.

## Theoretical/Conceptual Notes

The organizing insight, five instances deep (design §III.1): concerns
from one layer wearing another layer's name — gate (act-word on
deciders), judgment missing its subject, one word for two registries,
operational failure smeared into `:indeterminate`, `:policy` naming a
criterion-layer datum. Each fix was a factorization. The layer stack:
observe → judge → act, parameterized by criterion then policy;
judgments are ⟨ref(subject), verdict, findings⟩; two modeling layers
(abstract/lowered) related by `lower ⨟ erase = id`; composition is
`⨟` only, `∘` is banned. The living tension: aggregation
(findings → file verdict) keeps behaving like policy — the file-level
keyword verdict is documented as a conservative projection of
⟨verdict-over-decided × coverage⟩, and O3 will eventually decide where
that fold lives.

## What Worked Well / What To Do Differently

Worked: decision-register-first documents (renames cite decisions);
one-semantic-change-per-batch isolation; golden checks as proof of
behavior-neutral moves; empirical probing before registering claims;
background integration runs with scheduled check-ins; fixing forward
with disclosure rather than history rewrites. Do differently: state
aggregation/fold semantics as explicit design decisions up front
(the ranking incident); inventory-check prompt premises against the
lockfile/repo, not memory (the F14 framing).
