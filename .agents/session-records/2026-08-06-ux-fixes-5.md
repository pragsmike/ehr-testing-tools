# 2026-08-06 — UX fixes 5: the help wraps like it means it — hanging indents, gated width

## Scope

Session prompt naming AR-U5-0 through AR-U5-4. Prior: ux fixes 4
landed and was design-channel-verified (`7837fac`,
`notes/adr/0062-ux-fixes-4.md`) — the arc's B-4 finding split into a
content half (session 4, done) and a mechanism half (this session, the
arc's last fix). Content stayed untouched; only how those words wrap
at a real terminal changed. Full account, rulings verbatim, both red
transcripts, the `docs/cli.md` disposition, and before/after
transcripts: `notes/ADRs.md` ADR-0063.

## What landed

`bases/cli/src/ehrt/cli/help.clj` gained a private
`default-wrap-width` (80), `wrap-lines` (greedy word-wrap, spaces
only, an over-width single token lands alone unbroken), and
`wrap-with-hanging-indent` (prefix + word-wrapped text, continuation
lines indented to the prefix's own length). Every render function that
emits a rendered-string-position value — `render-flag`,
`render-exit-codes`, `render-verb`'s doc/positional-doc,
`render-group`'s doc/positional-doc, `render-top-level`'s top-level-doc
and per-group summary line — now routes through it, each at its own
layout's description-start prefix. Each threaded render function
gained an optional trailing `width` arg (default 80) purely so tests
could compare an 80-column render against an effectively-unwrapped one
— not a CLI-facing knob; `core.clj` is untouched, no flag reads it.

## Red-first, two ways (AR-U5-2)

**(a) The width test** ran against `help.clj` reverted to `7837fac`'s
content: `Ran 2 tests containing 266 assertions. 83 failures, 0
errors.` The worst offenders matched the audit's own B-4 finding
exactly — the top-level doc line at 482 columns, `corpus generate`'s
verb doc at 404. Green after the fix, 0 failures, part of the full
827-assertion run.

**(b) The content-preservation property** has no meaningful runtime
red against a renderer that does no wrapping — nothing exists to
strip. Against the pre-wrap tree this section fails to *compile*
(private functions and a `width` arg that don't exist yet), a
stronger form of "doesn't exist," disclosed in ADR-0063 rather than
forced into an artificial red. Once the mechanism landed, proven two
ways: a spec-derived round-trip test on `wrap-lines` itself (joining
wrapped lines with single spaces reconstructs every rendered-string
value in `cli-spec` exactly), and a whole-page test comparing an
80-column render against a 100000-column one with all whitespace runs
normalized — equal only if wrapping changed no content.

To get a genuine runtime red for (a) without a compile error blocking
the whole test namespace, the (b) section was held out via a temporary
`(comment ...)` block for that one run, then restored before
implementing the fix — see the ADR's own disclosure of this technique.

## `docs/cli.md` disposition (AR-U5-3)

Determined by inspection: `docs/cli.md` renders through
`components/docs-tooling/.../docsgen.clj`'s own separate

can't require bases, so they can't be one renderer). Confirmed
empirically: `make cli-doc` after the wrap landed produced a
byte-identical file, no diff. Left untouched, correctly.

## Judgment calls and their ratification status

- **The unbroken-token exception is real, not hypothetical, in
  today's spec.** Both `--config` flags (`corpus generate` and `sim
  run`) share one 78-character `(:pathway/:pathways/...)` token that,
  even alone on its own line under a 12-column indent, runs to 90
  columns — the width test's own exception clause (a too-long line
  explained entirely by one space-free token) covers it; disclosed in
  ADR-0063's after-transcript rather than silently passed over.
- **The `width` parameter is an internal testability seam, not a
  scope violation of "terminal width stays a constant."** AR-U5-4
  forbids a user-facing `--width`/`COLUMNS` affordance; it says
  nothing about render functions taking an optional arg so tests can
  exercise both the real (80) and an effectively-unwrapped width.
  `core.clj` never reads it and no flag exposes it — read as within
  AR-U5-1/2(b)'s own testability needs, not the forbidden affordance.
- **AR-U5-2(b)'s content-preservation test is spec-derived, per the
  ruling's own words ("so future strings are covered"), rather than
  hand-listing today's surfaces** — it walks `cli-spec` the same way
  `help-voice-test` already does, so it automatically covers any
  string this repo's spec grows later.
