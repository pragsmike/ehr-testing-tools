## 3. Judgment calls and their ratification status

**(a) `docs/cli.md` is generated — step 2 could not be done as
written. UNRATIFIED, disclosed.** The step says to edit `docs/cli.md`;
that file's own header reads *"GENERATED by `make cli-doc` from the
CLI help spec in `bases/cli/src/ehrt/cli/help.clj` -- do not
hand-edit"*, and CI diffs docsgen freshness, so a hand-edit is red
twice over. The ruled text can only reach the three rows through
`cli-spec`. That collides with this session's own fence, *"no src
change beyond step 1."*

Only one reading is defensible — the other fails CI — so this was
taken as fix-forward WITH DISCLOSURE per
`rulings.md#R-stop-only-on-two-defensible-readings`, not a stop. **The
fence is recorded as breached, deliberately, once.** The edit changed
three `:doc` description strings and nothing else; no `:flags` vector
moved, so the flag whitelist and the CLI's accepted surface are
untouched. `docs/cli.md` was regenerated by `make cli-doc`, not
edited.

Worth a ruling for the future: a session prompt that fences `src` and
also asks for a change to a generated doc has asked for two
incompatible things. The fence should name the generated surfaces it
does not mean to cover, or the step should name `help.clj` directly.

**(b) `:capacity-exhausted` was documented with its consequence, not
only the ruling's clause. UNRATIFIED.** The ruling gives ":capacity-
exhausted is the run refusing an arrival it cannot place". True, and
written as given — but a consumer needs the part that follows from it:
it is a `result`, not a state (`components/sim/src/ehrt/sim/run.clj`
line 790), so the run STOPS, no corpus is produced, and `check-all`
never runs. A consumer who reads "refusing an arrival" as a soft skip
waits for output that is not coming. Verified against
`components/sim/docs/clinical-realities.md` and
`components/sim/test/ehrt/sim/run_test.clj` before it was written.

**(c) The F1 addendum's claim was verified, not assumed.
UNRATIFIED, low stakes.** `components/sim/src/ehrt/sim/run.clj`
requires `ehrt.person-simulator.interface` (line 36) and calls
`initial-persona` (line 206) and `persons` (lines 212, 216). The F1
paragraph itself is byte-identical; the addendum is a new paragraph in
the same docstring and no other docstring line changed.

**(d) The ruled `--patients` suffix is a plain path, not a markdown
link. UNRATIFIED.** The same string renders in `ehrt help` at a
terminal, where markdown link syntax would be noise. The side effect
is that link-footnote-gate check 1 does not scan it, since that check
matches `](...)` — noted rather than relied on.

**(e) Arrow glyph matched to the page. Not a judgment call worth
ratifying**, recorded only because it was a deliberate second edit:
the new bed-cycle sentence uses `→`, matching the `:bed-cycle` row
already on that page, rather than the ASCII `->` first written.
