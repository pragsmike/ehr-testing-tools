## Judgment calls and their ratification status

- Interface widths for both new components: derived strictly from grep
  evidence against real call sites (filtering out the many docstring-
  prose false positives this codebase's heavily-annotated style
  produces — `facility/provider` as an English compound noun,
  `:pathway/:pathways` as keyword enumeration, etc.), never from
  judgment about what "should" be exposed. Recorded in ADR-0025, not a
  live judgment call needing separate ratification — AR-6 in the plan
  already ruled the method.
- The fixture cross-component resource-sharing pattern (S2's
  `components/sim-trajectory/test/ehrt/sim/fixtures/*` read by
  `engine_test.clj`, which stays in residual `sim`) is a judgment call:
  resources aren't `poly check`-visible, so this is an implicit
  coupling a component-boundary reviewer could miss. Justified in
  ADR-0025 by precedent (`components/sim/resources/sim/modules/*.json`
  already works this way, read by both `run.clj` and the vendored-
  module tests) and by the alternative being worse (copying the
  fixture file would risk drift). Not escalated — matches an existing,
  already-accepted pattern in this codebase, not a novel risk.
- Two structure-currency/reading-set-budget doc edits went slightly
  beyond the strict "move the four/three files" scope (updating the
  Dependency-direction bullet in AGENTS.md, the projects-table rows in
  architecture.md) — these are the direct, unavoidable consequence of
  a real gate this workspace already runs, not scope creep; called out
  here so the author can see the full edit surface at a glance rather
  than inferring it from the diff.
