## Judgment calls and their ratification status

- **The validation point sits in `dispatch`, not inside `parse`/
  `babashka.cli`.** `parse` runs before `[group verb]` is known from
  `args` (a single flat, per-flag-type-only spec shared across every
  verb), so a per-verb flag allowlist can't live there. babashka.cli's
  own `:restrict` option WOULD enforce an allowlist, but throws an
  `ExceptionInfo` rather than returning a value — incompatible with
  this repo's result-not-throw doctrine (ADR-0004) — and is global,
  not per-verb, anyway. `validate-known-flags` runs in `dispatch`
  instead, right after `[group action]` is destructured and the final
  `opts` computed, wrapped as `(or (validate-known-flags ...) (case
  group ...))` — the same short-circuit shape `:help`/bare-invocation
  already use above it.
- **AR-U3-3's hazard was checked live, not assumed absent.** Directly
  exercised `babashka.cli` 0.12.79 (`clojure -M -e`) against every
  shape this repo's declared flags use: a declared flag's own arity
  correctly keeps a dash-prefixed VALUE (`--reference-date -20260101`,
  `--at -5`, `--utc-offset -05:00`) attached to its own key, never
  split into a spurious second flag; an undeclared flag falls back to
  the library's own pre-existing default heuristic (boolean when
  followed by another `--` token, else consumes the next token as its
  value regardless of what it starts with) — behavior already shipped,
  untouched by this session. Since the validator only ever inspects
  `(keys opts)` — the parser's OWN finished output, never raw tokens —
  it structurally cannot reclassify a value as a flag. No
  STOP-AND-REPORT was triggered.
- **`"gate"`'s bare, verb-less sniff-dispatch (D11) needed one named
  exception, not a generic "skip validation when the verb is
  unrecognized" rule.** A generic rule would have let every unknown
  flag through on the very common `ehrt gate PATH --typo'd-flag` shape
  (the action token there is a PATH candidate, not an unrecognized
  verb). Instead, bare gate validates against the UNION of `gate v2`'s
  and `gate fhir`'s own declared flags — the full reachable set before
  sniffing decides which one actually runs (never `v2-nist`, which
  bare gate can't reach by construction). Disclosed rather than
  silent: a stray `--profile` (v2-nist-only) alongside bare gate is
  not independently flagged by this union — harmless, since it was
  already inert there before this session too. Live-verified the
  union is scoped correctly: an EXPLICIT `gate v2 --profile ...`
  still rejects `--profile` as unknown for that specific verb.
- **AR-U3-1's data was already there; only the derivation fn was
  missing.** `help/cli-spec` (ADR-0013, DOC-1) already carried every
  verb's own `:flags` plus `:global-flags` — the register's own
  reading was correct. No existing fn turned that into a flag-keyword
  SET, though (the one existing coverage test, `command-pairs`, walks
  group/verb pairs, never flags) — `declared-flag-keywords` and
  `flag-validation-context` are new, small, and live in `core.clj`
  beside their only caller, not `help.clj` (AR-U3-5: no help.clj
  changes this session).
- **The near-miss helper is local, not reused — confirmed absent, not
  assumed.** A fresh grep across `components/kernel/src/` for any
  distance/similarity helper found nothing, the same discipline U4's
  own check applied (ADR-0060). `levenshtein-distance` is a small,
  local, standard iterative-DP implementation, verified against the
  classic `kitten`/`sitting` = 3 case before wiring it in.
- **Oracle bracket ends at this session's own fix commit (`c8c1c9c`),
  not this record's own closing commit** — following ADR-0059/ADR-0060's
  own precedent exactly, since a docs-only ADR/record commit carries
  no digest risk to check.

## Findings and HEAD landed

`bases/cli/src/ehrt/cli/core.clj` gains `declared-flag-keywords`,
`flag-validation-context`, `levenshtein-distance`,
`nearest-declared-flag`, `unknown-flag-error`, and
`validate-known-flags`, wired into `dispatch` immediately before its
own `case group` routing. Any flag token the parser resolves to flag
position that isn't declared for its verb (global flags ∪ that verb's
own declared set; gate's bare, verb-less form validates against the
union of `gate v2`'s and `gate fhir`'s own flags, D11) is now rejected
by name — `:category :unknown-flag`, `:flag`/`:verb` always present,
`:did-you-mean` present only when a declared flag is within
Levenshtein distance 2 (ties alphabetical) — at exit 2. The oracle
bracket (`e222908` → `c8c1c9c`) confirms all eleven vendored-root
golden digests byte-identical — this session touched only the
CLI-shell option-parsing/validation path, no emitted byte moved.
